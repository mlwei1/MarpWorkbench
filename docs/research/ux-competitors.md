## 0. 调研方法与证据分级（先说清楚可信度）

用户原话（转述）：**"我很喜欢 Marp，但在 VS Code 里用很不方便，主题选择也很不方便。希望基于 Marp 做一个 exe，设计核心是方便用户使用。"**

证据分级：

| 等级 | 含义 | 本次来源 |
|---|---|---|
| **A** | 已读取全文/原文，可引用具体内容 | 少数派 Awesome Marp 长文、CSDN《Marp 精华总结（三）高级篇》 |
| **B** | 搜索引擎可检索到的原始页面（GitHub issue / Discussion / 官方文档 / 帮助中心 / MDN），标题与链接可核实，正文受网络限制未逐字读取 | marp-vscode / marp-cli issue、marp-team Discussion、Obsidian 中文论坛、Slidev / Pitch / Canva / iA 文档、MDN、Microsoft Q&A |
| **C** | 产品公开形态的行业观察或推断，落地前需实测 | Deckset、Marp Web 在线形态、Jupyter 具体交互细节 |

> **网络环境说明（可复核）**：本机 `web_fetch` 直连 github.com、sli.dev、ia.net、help.pitch.com 均超时（DNS 可解析、出网被拦）；sspai.com 与 CSDN 可直连并已读全文。因此 GitHub 类证据以"可检索到的 issue/讨论标题 + 链接"为准，未虚构正文；推断均标 C。Reddit / B站未检索到高质量且可核实的 Marp 讨论，故不作为证据（不硬凑）。
>
> **产品形态变更的影响（重要）**：本报告 §2（VS Code 痛点）、§4（主题 UX）结论与形态无关，继续有效；§5 起的文件/导出/生命周期/竞品结论按"本地服务 + 浏览器 UI"重写。

**一句话结论**：Marp 生态的**内容侧（Markdown 写作）已经很好，问题全在"格式侧"**——主题选择/定制是纯开发者工作流（改 YAML front-matter、手写 CSS、改 VS Code settings.json、自行装字体），且缺少"所见即所得的主题预览"和顺畅的导出/演讲/图片管理闭环。改为"本地服务 + 浏览器 UI"后，产品定位应是：**双击即用的 Marp 工作台**——把 Marp 的格式决策层做成 GUI（主题画廊 + 一键全 deck 预览 + 零摩擦导出），同时把"网页 UI 不可靠"的顾虑用**本地工作区 + 自动保存 + 可恢复现场**补回来。

## 1. 目标用户画像与核心场景

| 画像 | 是谁 | 痛点强度 | 关键诉求 |
|---|---|---|---|
| **P1 技术型知识工作者**（当前 Marp 主力用户） | 程序员、研究生、技术讲师，已用 VS Code + Marp 插件 | ★★★★★ | 快、不被插件配置折腾；多屏演讲；导出 PDF 交作业/资料 |
| **P2 Markdown 爱好者 / 内容创作者**（增长盘） | 少数派/知乎读者、写公众号/课程的人，会 Markdown 但不会 CSS | ★★★★★ | "选个好看的主题"就够了，不想碰 CSS/settings.json |
| **P3 临时汇报者**（转化盘） | 学生、职场人，被要求交 PPT，反感 PowerPoint 排版 | ★★★★ | 打开就能写、选主题、导出 PPTX 发给别人 |

三类用户共同点：**都认为"选择主题"应该像选 PPT 模板一样点一下就好**，而不是"改代码"。这直接对应用户原话中的"主题选择也很不方便"。
对本地 Web 形态的额外要求：**必须让用户相信"我的文件在我电脑上、不会丢"**——这是 P2/P3 用户接受"网页 UI"的前提。

### 2.3 用户最痛的 Top 3（给项目计划用）

1. **主题是"代码活"而不是"选择"**：改 front-matter、手写 CSS、注册 settings.json、装字体（T2/T3/T4/T10）。这是用户原话的直接来源，也是本产品最大的差异化机会。
2. **没有"选之前先看"的主题预览/画廊**：必须改完才知道长什么样，且预览≠导出（T1/T4/T8）。Marp 官方与 VS Code 插件都没有主题画廊。
3. **工作流割裂**：找导出命令、图片路径、演讲者模式、长文档预览同步，都不像"一个产品"（T7/T9/T11/T12）。

> 北极星指标建议：**"从双击 exe 到导出第一份 PDF 的完成时间"**（目标 ≤3 分钟）与 **"换主题操作步数"**（目标 ≤2 步：打开画廊、点一下）。当前 VS Code 方案换主题约需 6~10 步 + 查文档。

## 3. 竞品拆解

### 3.1 本地 Web 形态参考（本形态最直接对标，优先级最高）

形态本质：**exe 是本地服务的壳，浏览器是 UI，文件在磁盘**。这类产品用户已经见过很多，UX 有成熟先例可抄，也有共同的坑（"关掉窗口是不是就没了？""我的文件在哪？""导出怎么这么麻烦？"）。

| 参考产品 | 它怎么处理"本地文件 + 浏览器 UI + 导出" | 可借鉴 | 坑 / 我们的差异化 |
|---|---|---|---|
| **Marp CLI `--server`** | 本地起 HTTP 服务，浏览器中浏览/预览 Markdown 幻灯片文件列表，配合 watch 可边改边看（[marp-cli Server Mode（DeepWiki）](https://deepwiki.com/marp-team/marp-cli/4.1-server-mode)（B）） | 证明"Marp 渲染 + 本地服务 + 浏览器"工程可行；文件列表 + 预览页的最小信息架构 | 无文件管理（新建/最近/导入）、无主题画廊、导出仍需另开命令行 → **我们的产品化空间就在这里** |
| **Jupyter Notebook** | 本地服务 + 浏览器；以目录为工作区；**自动保存 + checkpoint 历史**；`File → Download as` 导出 PDF/HTML；URL 带 token；用户心智"服务在后台，关终端就停"（[Jupyter 使用教程](https://programminghistorian.org/en/lessons/jupyter-notebooks)、[Jupyter 保存说明](https://csuf.screenstepslive.com/m/129011/l/1958629-how-to-save-your-work-from-jupyternotebook-jupyterlite)）（B/C） | ①工作区目录模型 ②自动保存+checkpoint（历史版本）③"Download as"式导出菜单 ④token 保护 localhost | 导出 PDF 依赖 nbconvert、体验一般；"关终端就没了"的心智要避免 → 要做**无黑窗口 + 空闲自动退出 + 可恢复现场** |
| **Slidev dev server** | `npm run dev` 起本地服务，浏览器热更新；导出用 CLI 调 headless Chrome（[Slidev 导出文档](https://sli.dev/guide/exporting.html)）（B） | 本地服务 + 热更新的开发者体验 | 导出不在浏览器 UI 内、需要终端 → **我们把"一键导出"做成 UI 一等按钮**是明确差异 |
| **Obsidian**（本地优先心智，非 web） | 桌面应用（Electron），但核心信任模型是"vault 文件夹 + 纯文本 + 软件只是视图"，插件生态丰富 | **信任模型**：文件在本地、明文、可被其他工具打开；自动保存无感 | 不是浏览器形态；但可借鉴其"工作区=普通文件夹"的设计，降低"网页会不会拿走我文件"的顾虑 |
| **Notion 本地应用** | 本质是云服务的壳，不是本地文件应用 | 无（反例） | 反例说明：用户能感知"数据在云端"vs"数据在本地"→ 我们明确宣传**离线可用、文件在磁盘、无账号** |
| **VS Code Tunnel / code-server** | 本地/远端服务 + 浏览器访问本机文件；token/127.0.0.1 绑定等安全模型成熟（[VS Code Tunnel 实践](https://www.cnblogs.com/youdias/p/19368710)）（B） | ①仅绑定 127.0.0.1 ②URL token ③浏览器 UI 读写本地文件的成熟边界 | 安全模型必须照抄，否则本地任意程序/网页都可能访问我们的服务 |

**从形态参考得到的 5 条硬结论**

1. **打开即用感**：双击 exe 后用户只应该看到浏览器页面（≤5 秒），不能看到黑色控制台窗口/端口号/技术日志（或至少默认隐藏）。Jupyter 的"关终端就停"是反面教材。
2. **文件必须"看得见"**：首页要有明确的工作区路径展示与"打开所在文件夹"按钮；文件树的根是真实磁盘目录（默认 `文档/MarpStudio`），不是浏览器虚拟存储。这解决"网页 UI 不可信"。
3. **导出必须一键**：这是浏览器形态最大的体验风险。默认走"本地服务调用 Edge headless 打印"，而不是让用户按 Ctrl+P 自己"另存为 PDF"（详见 §5.3）。
4. **服务生命周期要可预期**：关页面不等于退出应用，但用户必须随时能"退出"；空闲自动退出 + 单实例打开已有实例，是这类应用的标准做法（对标 code-server/VS Code Tunnel 的本地服务心智）。
5. **本地 Web 形态的红利**：无 Electron 体积、免安装、更新只是换 exe、可多标签多窗口、可直接用系统 Edge；代价是窗口/托盘/拖拽等系统集成弱 → 用**首启引导 + 自动保存 + 恢复现场**补偿。

### 3.2 演示工具的主题 UX 拆解

| 竞品 | 形态 | 主题选择交互 | 预览 | 导出 | 可借鉴 | 不借鉴 |
|---|---|---|---|---|---|---|
| **Marp for VS Code** | VS Code 插件（当前用户方案） | 改 front-matter `theme:` + settings.json 注册 CSS；无画廊 | 侧边预览，滚动同步不稳 | 命令面板导出 PDF/PPTX/PNG/HTML，入口深 | Markdown 即时渲染、front-matter 生态 | 格式操作对非开发者不友好 |
| **Marp CLI** | 命令行 | `--theme` 参数/CSS 文件 | 无 GUI（server 模式可预览） | 能力强（PDF/PPTX/HTML），依赖 Puppeteer | 导出工程质量、离线渲染思路 | 0 GUI，普通用户不可用 |
| **Marp Web（官方 Web 形态，web.marp.app）** | 浏览器 | **未验证**（当前网络打不开） | 实时 | 以官方为准 | "零安装、打开即用"的心智 | 需联网、文件管理弱（C，待验证） |
| **第三方在线 Marp 编辑器（Markflow）** | Web | 编辑 + Marp 预览 | 实时 | 在线导出 | 证明"在线 Marp 编辑"有真实需求（[dev.to](https://dev.to/nkmelndz/markflow-the-ultimate-free-online-markdown-editor-with-marp-support-kpk)） | 我们做本地离线，不做在线优先 |
| **Slidev** | 开发者向 Web 幻灯片 | **主题作为 npm 包**，`theme:` 指定；官方主题画廊以截图卡片展示；支持 addon | Dev server 热更新极快 | CLI + headless Chrome | ①画廊卡片形态 ②一键试主题 ③主题可分发生态（[主题画廊](https://sli.dev/themes/gallery.html)、[theme-addon](https://sli.dev/guide/theme-addon.html)） | npm 安装=非开发者门槛，正是我们要消除的 |
| **iA Presenter** | macOS/iPad 商业应用 | **Design 面板**集中管理设计/主题/配色/字体，选中即全局生效 | 编辑区即排版效果 | PDF/HTML 等 | ①"设计"作为顶级入口 ②少量精选主题 ③面板内实时切换（[Design 支持页](https://ia.net/presenter/support/visuals/design)） | 主题数量少、闭源；我们"精选+可扩展" |
| **Obsidian + Marp 插件** | 笔记软件 + 社区插件 | 插件设置页配置主题路径/自定义 CSS；front-matter 控制 | 内置预览 | 依赖插件/CLI，自定义主题导出常有坑（[论坛帖](https://forum-zh.obsidian.md/t/topic/44135/1)） | "文件夹即工作区"本地文件心智 | 设置分散、导出不一致（[obsidian-marp-extended](https://github.com/shuuul/obsidian-marp-extended)） |
| **Deckset**（macOS） | 商业桌面应用 | **主题列表 + 即时全局预览**，切换主题不改 Markdown；主题是核心卖点 | 实时 | PDF/图片 | "主题选择器"就是这个品类最核心的 UI；少而精（[官方文档](https://docs.deckset.com/)） | macOS only、闭源；Windows 空白是我们机会（C） |
| **Pitch** | 在线协作演示 | **Slide styles / 主题风格**面板查看缩略图，可一次性应用到全部/部分幻灯片 | 实时 | PDF/PPTX 等 | ①"应用到全部幻灯片"显式开关 ②样式面板缩略图（[Pitch: Work with slide styles](https://help.pitch.com/en/articles/4063049-work-with-slide-styles)） | 重协作/云，超出 MVP |
| **Canva** | 在线设计 | **模板/主题库**：分类 + 搜索 + 大缩略图；换模板保留内容、提示影响范围 | 实时 | PDF/PPTX/PNG 等 | ①分类/搜索/收藏解决选择过载 ②换模板前"保留内容"提示（[Canva 帮助](https://www.canva.cn/help/change-template-cn/)） | 模板≠主题，重排会破坏 Markdown 结构 |

### 3.3 三条判断

1. **"主题"必须是产品的一级公民**：Deckset 把它做成核心卖点、iA Presenter 有独立 Design 面板，而 Marp 系把它藏在 front-matter/CSS 里。我们与它们的差距不是"能不能用 Marp"，而是**格式决策的 UX 层缺失**。
2. **画廊是行业标准**：Slidev 主题画廊、Canva/Pitch 样式面板证明"缩略图卡片 + 点击预览"是用户预期；Marp 生态至今没有面向普通用户的主题画廊——这是最直接的产品空位。
3. **本地 Web 形态有明确对标但无直接竞品**：Marp CLI server 证明可行性但没有产品化；Jupyter/code-server 证明本地服务+浏览器可行但导出/主题体验差。**"Marp 渲染 + 本地服务 + 浏览器 UI + 主题画廊 + 一键导出"目前是空位。**

## 4. 主题选择的 UX 设计建议（本产品核心）

### 4.1 主题画廊展示什么（卡片信息设计）

每张主题卡片（约 220×140px 缩略图 + 元信息）：

- **真实内容缩略图**：用**用户当前 deck 的前 3 页**渲染（封面页 + 内容页 + 代码/表格页），而不是主题自带示例图——"点之前就看到自己的内容长什么样"。
- **主题名**（`@theme` 注释里的名字，Marp 规范）+ 来源（内置/社区/我的）。
- **风格标签**：`简约` `学术` `商务` `深色` `创意` `科技` 等 1~2 个场景标签（不只靠颜色分类）。
- **配色小样**：3 个色块（背景/主文字/强调色）。
- **字体信息**：衬线/无衬线/等宽，是否内置中文字体（"含中文字体 ✓"）。
- **状态徽标**：`推荐` `最近使用` `收藏` `我的主题`。
- **悬停大图预览**：hover 卡片 → 预览区临时全 deck 切换（不写文件）；移开复原。
- **点击 = 应用**：点击卡片即写回当前 deck 的主题设置，**一步完成**；顶部 undo toast："已应用「学术蓝」，撤销"。

### 4.2 "点一下立刻预览全 deck"的交互规格

- 点击主题 → **右侧主预览立即全 deck 重渲染**（不是只换缩略图），增量渲染 ≤300ms。
- 编辑器区域**不弹窗、不跳转**；主题面板为右侧抽屉（约 360px，覆盖预览区），可随时收起。
- 主题变更**不打断写作**：光标与滚动位置保持。
- 提供"**只看当前页 / 浏览整 deck**"两种预览模式，方便检查封面/目录/结尾页。
- **试用机制**：卡片"在预览中试试"→ 临时态预览，`Esc` 复原；正式应用才写入。
- 面板顶部固定：搜索框、分类 Tab（全部/推荐/学术/商务/深色/我的）、收藏筛选。

### 4.3 自定义主题的完整生命周期（编辑/导入/保存/分享）

```
入口（主题面板底部"＋ 新建 / 导入"）
 ├─ 基于内置主题复制 → 主题编辑器（左 CSS + 右上实时预览 + 右下可视化参数）
 │    可视化参数：主色/背景色/强调色、正文字号、标题字号、字体（内置可选）、页码开关
 │    → 保存 = 自动写 .css 到「工作区/.marpstudio/themes」或用户主题目录
 ├─ 导入 .css（拖拽/文件选择）→ 解析 /* @theme name */，检测缺失字体/import → 一键注册
 └─ 分享：导出主题包（.css / .zip 含 README）→ 他人拖入即导入
```

- **隐藏所有 Marp 机制**：不要求用户知道 `/* @theme */`、`markdown.marp.themes`、settings.json；由应用生成。
- **预览与导出同源**：主题编辑器预览与 PDF 导出使用同一渲染器。
- **失败友好**：CSS 语法错误 → 行内提示 + 继续用上一个有效版本渲染，不白屏。
- **主题信息可读**：解析 `@theme` 名称、`@size`（16:9/4:3）、`@import`、`@auto-scaling`，卡片显示"16:9 / 含字体 / 依赖 xxx"。

### 4.4 离线主题包 vs 在线主题市场

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 纯离线内置主题包 | 启动即用、无网络、体积可控（每个主题几十 KB CSS） | 更新慢、数量有限 | **MVP 唯一方案**：内置 12 套精选（中英文、深浅色、学术/商务/创意） |
| 在线主题市场 | 可扩展、社区贡献、有传播性 | 需服务端/审核/信任、离线不可用、MVP 成本高 | **P1**：先做"导入 .css / 主题仓库 URL"，市场后期 |
| 混合（推荐） | MVP 离线即可用，P1 接市场 | — | **推荐**：主题=本地文件优先；市场只是"发现/下载"入口 |

## 5. 本地 Web 应用形态的 UX 设计（v1.1 新增）

### 5.1 三个设计原则

1. **本地优先**：无网络可用、无账号、文件是普通 `.md`；浏览器只是视图，**数据在磁盘**（用户可见、可被 Marp CLI/VS Code 打开）。
2. **零权限摩擦**：默认使用内置工作区（服务端直接读写），**不要求**用户在浏览器里授权文件访问；只有"打开任意磁盘文件"才走 File System Access API / 拖拽导入。
3. **可恢复**：页面刷新/误关/浏览器崩溃后，重开即回到现场（deck、滚动位置、主题面板状态），因为状态在服务端 + localStorage。

### 5.2 文件怎么管理（核心决策）

| 方式 | 交互 | 优点 | 缺点 | 产品定位 |
|---|---|---|---|---|
| **A. 内置工作区（推荐默认）** | 首页文件列表；新建/导入/重命名/删除；根目录 `文档/MarpStudio`，可改；"打开所在文件夹"按钮 | **零权限提示**、自动保存天然可行、最近文件/回收站/历史版本都归我们管 | 文件不在用户原有仓库里（需导入） | **主路径**，覆盖 P3/P2 及大多数 P1 |
| **B. 打开任意本地 md（File System Access API）** | "打开文件/文件夹"→ 系统文件选择器（`showOpenFilePicker`/`showDirectoryPicker`）；授权后直接读写原文件 | 就地编辑 git 仓库/原有目录，符合 P1 习惯 | 需要用户手势与浏览器授权；刷新后通常需重新授权（持久化权限有条件）；仅 Chromium（Edge/Chrome 支持，[MDN showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)） | **高级路径**（P1 用户）；失败/不支持时降级为拖拽上传复制到工作区 |
| **C. 拖拽导入/导出** | 把 `.md`/图片拖进页面即导入工作区；导出文件下载到默认下载目录或工作区 `exports/` | 最自然、跨浏览器可用（`<input type=file>`/DataTransfer） | 导入=复制，用户需理解"导入后在工作区里" | **辅助路径**，同时是首启引导里的"从已有 md 开始" |

**自动保存与恢复（必须做到用户无感）**

- **自动保存**：编辑停止 500ms~1s 防抖写盘 + 每 30s 强制落盘；状态栏显示"已保存 12:03:45"；写盘失败（磁盘满/权限）必须显式红字警告，不能静默。
- **最近文件**：首页 + 菜单；路径失效自动灰显/提示。
- **刷新/关页恢复**：URL 带 `?deck=<id>`；服务端保存当前 deck 与视图状态；localStorage 存预览缩放/主题抽屉开关/滚动位置；重开 ≤1s 回到现场。刷新时若有未保存改动，`beforeunload` 提示（正常自动保存后不会出现）。
- **历史版本**：每次手动保存（Ctrl+S）+ 每 5 分钟自动快照到 `.marpstudio/history/<deck>/<时间戳>.md`，保留最近 30 个；"历史版本"面板可查看/另存/回滚（diff 视图放 P1）。
- **安全边界**：服务仅绑定 `127.0.0.1`；URL 带一次性 token（防本机其他网页扫描端口）；拒绝非本机 Origin；不监听局域网（避免 Windows 防火墙弹窗，绑定 127.0.0.1 即可）。

### 5.3 浏览器里导出 PDF 的摩擦设计（本形态最大风险）

| 方案 | 体验 | 风险 | 结论 |
|---|---|---|---|
| **A. 本地服务调用本机 Edge headless 打印**（`msedge --headless --print-to-pdf`） | 用户点「导出 PDF」→ 进度 → 完成 → "打开 PDF / 打开所在文件夹"，**全程无对话框** | Edge 路径/版本差异；headless 参数与页眉页脚行为需处理（[Microsoft Q&A：Edge headless 去页眉页脚](https://learn.microsoft.com/en-nz/answers/questions/5729862/how-to-print-to-pdf-with-no-header-and-footer-when)）；有版本 regress 报告（[Microsoft Q&A：headless 不再保存 PDF](https://learn.microsoft.com/en-gb/answers/questions/5579903/msedge-exe-does-not-save-html-file-as-pdf-in-comma)）（B） | **默认方案**。检测 Edge → 缺省回退方案 B；失败给出可读原因 + 重试 |
| **B. 浏览器系统打印对话框（Ctrl+P → 另存为 PDF）** | 用户要自己选"另存为 PDF"、处理页眉页脚、选保存位置 | 摩擦大、易出错、每页尺寸不精确 | **兜底方案**：Edge 不可用时明确引导（"已为你打开打印页，请选择'另存为 PDF'"） |
| C. 服务端重打包（puppeteer/Electron） | 一键 | 体积/依赖与"单文件便携 exe"冲突 | 交桌面封装组评估，非 UX 首选 |

**一键导出 PDF 的交互规格**

1. 顶部「导出」→ 选 PDF → 导出面板显示小预览（首页缩略图）、页数、尺寸、是否含备注/页码。
2. 点「导出 PDF」：按钮进入 loading（防重复点击），进度显示"渲染第 3/12 页"；可取消。
3. 服务端渲染 → 调 Edge headless 打印 → 文件写入 **工作区 `exports/`**（文件名 `deck-YYYYMMDD-HHmm.pdf`，可改）。
4. 完成 toast："已导出 12 页 PDF" + 两个按钮：**打开 PDF**、**打开所在文件夹**（服务端调 `explorer /select,` 实现，Windows 上很自然）。
5. 失败：错误信息要可执行（如"未找到 Edge，请安装 Microsoft Edge，或改用浏览器打印"），提供重试与日志入口。
6. 导出与预览必须同源同参数；导出后提供"重新导出最近一次设置"（记住上次格式/路径）。

### 5.4 多标签/多窗口、首启、更新、退出

- **多标签**：每个标签页 = 一个 deck（`?deck=id`）；同一 deck 在多个标签打开 → 提示"已在另一标签页打开"（只读 or 接管）；P1 再做 WebSocket 实时同步。浏览器多窗口天然支持（演讲者模式就是 `window.open` 弹出，必须在用户点击手势内调用，避免被拦截）。
- **首次启动引导（3 步，可跳过，≤60 秒）**：① 选择/确认工作区位置（默认 `文档/MarpStudio`，显示真实路径）→ ② 环境检查（默认浏览器、Microsoft Edge 是否可用，用于 PDF 导出）→ ③ 打开示例 deck，引导"点主题 → 看效果 → 导出 PDF"，**首启 3 分钟内完成一次导出**。用过 VS Code 的用户可跳过。
- **更新提示**：便携 exe 不能静默自更新（运行中文件被锁）。启动异步检查新版本 → 首页/设置里横幅"发现 v1.2 → 下载新版本"；下载后提示"退出后替换 exe"；检查失败静默、绝不阻塞使用。
- **退出方式**：关闭浏览器页面 **≠** 退出应用。设计三层：
  1. Web UI「设置 → 退出应用」：先保存所有 deck，再停止服务（标签页显示"已退出，可关闭页签"）。
  2. 空闲自动退出：无页面连接持续 10 分钟（可配置 5/10/30/从不）→ 服务退出，避免后台残留。
  3. 托盘图标（P1，提升可预期性）：显示"服务运行中 / 退出"。
- **单实例**：重复双击 exe → 检测到已有服务 → 直接打开已有 URL（不新起端口）。端口被占用 → 自动选下一个空闲端口，并把 URL 写入 clip/提示。

### 5.5 浏览器端键盘与交互差异

- 拦截 `Ctrl+S`（保存/快照）、`Ctrl+Shift+S`（另存为）、`Ctrl+N`（新建 deck）、`Ctrl+O`（导入）、`Ctrl+P`（改为打开导出面板而不是浏览器打印），都要 `preventDefault`。
- 浏览器刷新/后退：`beforeunload` 只在有未保存改动时提示；SPA 内路由不受影响。
- 全屏/演讲：用 Fullscreen API + `window.open` 双窗方案；提示用户"将浏览器窗口拖到投影仪"（P1 可做"自动定位第二屏"，浏览器权限有限）。
- 拖拽：整页 drop zone（导入 md/图片/CSS 主题），带可视高亮；避免与浏览器默认"打开文件"冲突。
- 浏览器缩放：应用布局用 rem/响应式，1280~1920 宽度可用；提示用户不要用浏览器缩放代替应用缩放。

### 5.6 得与失（写给项目计划的风险认知）

- **得**：无 Electron 体积、免安装、开发迭代快、多标签多窗口免费、直接复用系统 Edge/默认浏览器、更新=换 exe。
- **失**：窗口/托盘/系统集成弱；依赖本机 Edge（导出）；浏览器权限限制（FSA 授权、弹出窗拦截）；用户对"网页里写文件"的信任需教育。
- **补偿设计**：首启引导讲清"文件在你电脑的哪个文件夹"、自动保存状态常驻可见、一键打开所在文件夹、退出/空闲行为可配置、错误可恢复（历史版本）。

## 6. MVP 功能清单（P0 / P1 / P2）

优先级依据：**用户价值（对"方便"的贡献）× 实现成本 × 与差异化的关系**。P0 ≤ 10 条。

### P0（必须有，首版即"好用"）

| ID | 功能 | 用户价值 | 成本 | 为什么是 P0 |
|---|---|---|---|---|
| **P0-1** | **双击 exe → 本地服务 → 自动打开浏览器首页**（无黑窗口；单实例/端口冲突处理；首启 3 步引导；空闲自动退出 + UI 内"退出应用"） | ★★★★★ | 中 | 产品形态的第一印象；任何"技术感"泄露都会毁掉"方便" |

| **P0-3** | 编辑-预览双栏实时预览（当前页同步、缩放、单页聚焦） | ★★★★★ | 中 | Marp 体验核心；解决 T11 滚动同步 |
| **P0-4** | **主题画廊**：内置 12 套离线主题、真实内容缩略图、hover 大图预览、`↑↓` 键盘切换、分类/收藏/最近使用、拖拽导入 CSS、点击即全 deck 应用 + 撤销 | ★★★★★ | 中 | **用户原话指向 + 最大差异化**；解决 T1/T2 |
| **P0-5** | **一键导出中心**：PDF（本地 Edge headless，进度→完成→打开所在文件夹）+ PPTX（位图）；失败可读提示与兜底引导 | ★★★★★ | 中高 | 解决 T7/T8/T9/T10；浏览器形态最大摩擦点必须产品化 |

| **P0-10** | 自定义主题：导入 `.css`、基于内置主题另存为、保存到本地"我的主题"、即时生效 | ★★★★ | 中 | 解决 T3/T4/T5/T6 入口；先"导入+另存"，完整可视化编辑器放 P1 |

> 首版定位一句话：**"双击就能用的 Marp 工作台"**——写作仍是 Markdown，但文件、主题、导出、演讲全部产品化；文件在本地磁盘、离线可用。

### P1（第二版，提升黏性与扩展性）

- 导出 PNG / HTML / 带备注 PDF；导出预设（分辨率/边距/是否含备注）与"重新导出上次设置"
- 主题包导出/分享、主题市场（浏览/下载/评分）、从 GitHub 主题仓库一键导入
- 主题可视化编辑器（调色盘、字号、字体下拉）
- File System Access API「打开任意本地文件夹/文件」高级路径（含授权引导与降级）
- 大纲拖拽排序、章节折叠、幻灯片搜索、历史版本 diff 视图
- 中文字体管理器（内置开源字体包、缺失检测与替换）
- 模板/封面页/目录页片段库；代码高亮主题、公式（KaTeX）/HTML 开关设置面板
- 多文件项目/工作区切换；多标签同 deck 实时同步（WebSocket）
- 托盘图标、系统通知、"导出完成后直接打开 PDF"偏好设置
- 自动更新提示与便携版替换引导；崩溃恢复增强

### P2（长期，非 MVP 必需）

- 云同步/协作、分享链接、评论
- AI 生成大纲/配图/美化（加分项，不做核心）
- 录制/直播、视频导出
- 插件系统、脚本 API
- 更多导出格式（Keynote/Google Slides 导入导出）

### 明确不做（写进计划，防跑偏）

- ❌ 可视化拖拽排版/自由画布：破坏 Markdown 纯文本工作流，与 Marp 生态不兼容，成本极高。
- ❌ 私有语法/私有项目格式：`.md` 必须可被 Marp CLI/VS Code 原样打开（兼容性是信任基础）。
- ❌ 在线优先/必须联网/强制登录：与"本地、离线、方便"定位冲突。
- ❌ MVP 阶段自研 Chromium 渲染导出：与"单文件便携 exe"体积目标冲突，优先复用系统 Edge。

### 7.3 三个核心用户流程（分步）

**流程 A：双击 exe → 新建 → 写 → 选主题 → 导出 PDF（目标 ≤3 分钟）**

1. 双击 `MarpStudio.exe` → 后台启动本地服务（无控制台窗口）→ 默认浏览器自动打开首页，显示工作区路径。
2. 点「＋ 新建演示文稿」（或 `Ctrl+N`），默认写入最小 front-matter（`marp: true`, `theme: <推荐默认>`）。
3. 光标落在编辑区，输入 Markdown；右侧预览实时跟随当前页；输入 `---` 新页，左侧缩略图即时增加。
4. 点顶部「主题」→ 右侧抽屉打开画廊；**点任意卡片** → 全 deck 立即切换（hover 可临时预览，Esc 复原）；关闭抽屉即完成（主题自动保存）。
5. 继续写作；状态栏显示"已保存 12:03:45"（自动保存，无需 Ctrl+S）。
6. 点顶部「导出」→ 选 PDF → 面板确认页数/尺寸/选项 → 点「导出」。
7. 进度显示"渲染第 8/12 页"（可取消）→ 完成 toast：「打开 PDF」「打开所在文件夹」。
8. 关闭标签页后服务空闲 10 分钟自动退出（或点「设置 → 退出应用」立即退出）。

**流程 B：导入现成 Markdown（目标：拖进来就能用）**

1. 在首页把 `.md` **拖进页面**（或「导入 Markdown…」/「打开文件夹…」）；文件复制/链接到工作区，出现在最近文件。
2. 应用解析 front-matter 与内容，识别是否为 Marp 文档；无 `marp: true` 时询问"作为 Marp 演示文稿打开？"。
3. **主题检查**：若引用未知主题（如 Awesome-Marp 的 `theme: awesome-blue`）→ 提示三选一：①从文件所在目录/工作区自动查找 CSS ②使用内置相似主题 ③手动导入主题文件。
4. **资源检查**：解析本地图片路径，缺失时列出清单（可定位/替换）；相对路径按 md 所在目录解析。
5. 进入编辑器，预览正常；标题栏显示文件路径与"已关联主题"。
6. 可直接导出或先换主题；导出时若有缺失资源，明确警告（不静默丢图）。

**流程 C：自定义主题（从"想改一点"到"保存复用"）**

1. 主题面板点「＋ 新建主题」→ 选择"基于内置主题 学术蓝"（推荐）或"空白主题"。
2. 主题编辑器：左侧 CSS（高亮+注释），右侧实时预览当前 deck，右下可视化参数（主色/背景/字号/字体/页码）。
3. 改参数或 CSS → 预览即时更新；语法错误报错到行并保留上一次有效渲染。
4. 点「保存」→ 命名（如"我的答辩蓝"）→ 自动写入本地主题库并注册到"我的主题"，当前 deck 立即应用。
5. 卡片更多菜单：重命名、导出主题包（.css）、分享给他人导入、删除（带确认）。
6. 下次开新 deck，"我的主题"分类下直接选用；归档到工作区后随文件一起可迁移。

## 8. P0 验收标准（"完成即好用"，可直接写进项目计划）

> 原则：每条都能"截图/点一下"验证，避免"已实现但不好用"。

| 对应功能 | 验收标准（完成即好用） |
|---|---|
| **P0-1 启动/生命周期/首启** | 双击 exe 到浏览器首页可交互 ≤5s（中等配置 Windows），全程无控制台黑窗（除非用户要求查看日志）；重复双击不会起第二个服务，而是打开已有页面；端口被占用自动换端口且用户无感；关闭所有页面后按设置（默认 10 分钟）自动退出服务，服务列表/进程可验证；「退出应用」按钮先保存再停服务，页面显示"已退出"；首启引导可跳过，完成一次"新建→写→选主题→导出"的示例路径。 |
| **P0-2 工作区/自动保存/恢复** | 默认工作区 `文档/MarpStudio` 自动创建且路径可在 UI 中看到/修改（"打开所在文件夹"可用）；编辑停止 1s 内落盘（界面上"已保存"时间更新，用磁盘文件时间戳核验）；强制结束服务进程再启动，未保存内容最多丢 1s；刷新/关页重开恢复同一 deck + 滚动位置 + 主题面板状态（≤1s）；最近文件 ≥10 条、失效路径灰显；历史版本保留最近 30 个快照，可回滚且回滚前自动留底；磁盘写入失败时状态栏红色警告且不显示"已保存"。 |
| **P0-3 双栏实时预览** | 输入后预览更新延迟 ≤150ms（本地 50 页 deck）；滚动编辑器时右侧自动定位"当前正在编辑的幻灯片"，不出现往复跳动；预览可缩放 50%~200% 与"适应窗口"；单页/全 deck 模式切换 ≤100ms 无白屏；刷新后帧率不劣化。 |
| **P0-4 主题画廊** | 内置 ≥12 套主题全部离线可用；卡片用**当前 deck 真实内容**生成缩略图；hover 预览与点击应用的全 deck 切换 ≤300ms；`↑↓` 可连续切换主题并即时预览；支持搜索 + ≥5 分类 + 收藏 + 最近使用；拖入 `.css` 即导入并出现在"我的主题"；误点应用可一键撤销且恢复原主题；切换主题后 front-matter/项目设置自动更新（用户不需编辑）。 |
| **P0-5 一键导出** | 点「导出 PDF」→ 无任何系统对话框 → 完成并给出「打开 PDF」「打开所在文件夹」；PDF 与预览逐页一致（封面/内容/代码/结尾 4 页人工对比，无主题/字号/颜色/换行偏差）；中文字体嵌入（PDF 可复制中文，换机器不变形）；相对路径图片 ≥99% 正确（样例含 20 张图）；16:9 精确 1280×720（或等价尺寸）、无多余页眉页脚与白边；50 页导出 ≤30s，进度可见可取消；Edge 缺失/失败时有可执行引导与"浏览器打印"兜底；PPTX 页数=幻灯片页数、16:9、PowerPoint/WPS 可直接打开无修复提示，并明确标注"图片版（不可逐字编辑）"。 |
| **P0-6 演讲者模式** | 点击「演示」在用户手势内弹出演讲者窗（不被浏览器拦截）；观众窗全屏、演讲者窗显示备注/下一页/计时/进度；方向键/点击翻页延迟 <100ms 且两窗同步；退出后回到编辑器且光标位置不变；无第二屏时降级为单窗模式并提示"拖到投影仪"；刷新演讲者窗不丢当前页。 |
| **P0-7 图片粘贴/拖拽** | `Ctrl+V` 粘贴剪贴板图片 → 自动保存到 `assets/`（重名加序号）并插入相对路径，预览 1s 内出现；拖入图片同理；删除图片后不静默删盘（提供"清理未使用资源"）；移动整个工作区后路径仍可用。 |
| **P0-8 front-matter 面板** | 常用项（主题、尺寸 16:9/4:3、页码、页脚、背景图、标题）均有可视化控件且双向同步；非法 YAML 给可读错误并保留原文；可一键切源码视图；不破坏用户自定义的未知字段。 |
| **P0-9 大纲/缩略图** | 自动按标题生成大纲（层级正确）；点击跳转并把光标定位到该页首个标题；缩略图与实际渲染一致、编辑更新 ≤300ms；100 页 deck 滚动流畅（无 >200ms 卡顿）。 |
| **P0-10 自定义主题** | 拖入 `.css`（含 `/* @theme name */`）→ 解析名称、加入"我的主题"、可一键应用且预览立即生效；可在内置主题上"另存为"并持久化；重启服务后"我的主题"仍在（文件在本地主题目录，可打开查看）；缺失字体明确提示"缺字体：xxx（影响导出）"而非静默回退；导出 PDF 使用同一主题。 |

**全局体验标准（跨 P0 的"好用"红线）**

- 所有耗时操作（导出、缩略图生成、服务启动）都有进度与取消，不冻结 UI。
- 所有破坏性操作（替换主题、删除主题、删除文件、清理资源）可撤销或有确认。
- 中文界面文案统一；错误提示必须给"下一步怎么做"，而非只报错。
- 兼容性：应用产出的 `.md` 必须能被官方 Marp CLI / VS Code 插件原样渲染（回归用例：3 个不同主题的示例 deck）。
- 安全/信任：仅监听 127.0.0.1；URL token 不可预测；不向局域网暴露；不上传任何用户内容（除用户主动检查更新）。
- 隐私说明可见：设置页有一页"你的文件在哪、应用访问了什么、有没有联网"。

## 11. 给项目计划的 8 条一句话结论

1. 产品定位：**双击 exe → 浏览器里的 Marp 工作台**——文件在本地磁盘、离线可用、无账号；把"选主题/导出/演讲/图片"做成点一下就完成的体验。
2. 第一优先级永远是**主题画廊 + 一键全 deck 预览**（P0-4），这是用户原话直接指向的、竞品未占领的空位。
3. 本地 Web 形态成败关键在**启动体验与导出摩擦**（P0-1/P0-5）：不能露黑窗口、不能走"Ctrl+P 另存为"；默认用本机 Edge headless 一键导出，并准备好兜底。
4. 信任基石是**内置工作区 + 自动保存 + 刷新恢复 + 历史版本**（P0-2），并且要在 UI 里让"文件在哪"随时可见可打开。
5. 第二优先级是**导出所见即所得**（P0-5），Marp 社区投诉本质是"预览≠导出"，一致性比格式数量重要。
6. 主题系统设计原则：**内置 12 套精选 + 我的主题（导入/另存 CSS）+ P1 再上市场**；推荐/分类/收藏/最近使用解决选择过载，浏览器端加 hover 大图与 `↑↓` 键盘切换。
7. 所有 Marp 机制（front-matter、settings.json、`@theme` 注释）都要**产品化隐藏**，但产出必须是标准 `.md`，可与官方工具互通。
8. P0 控制在 10 条内，验收标准按"完成即好用"（§8）逐条写进计划；服务生命周期、端口/单实例、token 安全、空闲退出这些"看不见的体验"同样要写进验收。
