## 1. 背景与问题

你的原话："我很喜欢 Marp，但在 VS Code 里用很不方便，主题选择也很不方便。"

调研（`ux-competitors.md` §2，含社区证据）把痛点归成 4 类：

| 摩擦 | 具体表现 | 后果 |
|---|---|---|
| **主题是"代码活"** | 换主题要改 YAML front-matter；自定义主题要新建 .css、写 `/* @theme */`、在 VS Code `settings.json` 注册、还要自己装中文字体（少数派/CSDN 教程、marp-vscode #100/#403/#418） | 普通用户根本用不起来，只能永远用默认主题 |
| **没有"选之前先看"** | 内置只有 default / gaia / uncover 三套且不好看；改完才知道长什么样；预览和导出还不一致（#418、marp-cli #584/#393） | 选主题靠猜，做出来的 PPT 不好看 |
| **工作流割裂** | 导出入口藏在命令面板；图片路径经常丢；没有真正的演讲者模式；长 deck 预览跳动（#559/#492/#530） | 每次做 PPT 都要"重新学一遍工具" |
| **分发困难** | 给同事一份 .md，对方要装 VS Code + 插件 + 主题 + 字体才能看 | Marp 只能自己用，成果传不出去 |

**机会：** Marp 生态"内容侧（Markdown 写作）已经很好，缺的是格式决策的 GUI"。把主题、导出、演讲、图片管理做成"点一下就好"，同时产出的仍是**标准 Marp Markdown**（可随时拷回 VS Code / marp-cli），这是当前市场的空位（Deckset 在 macOS 做成核心卖点，Windows 没有对等物）。

## 2. 产品定义

### 2.1 一句话与形态

**Marp 工作台**：Windows 便携单文件 exe。双击后本地起服务、自动打开默认浏览器，进入工作台。

```
双击 MarpWorkbench.exe（无黑窗，<1s 起服务）
        ↓ 自动打开 http://127.0.0.1:<随机端口>/?token=xxx
┌────────────────────────── 浏览器里的 Marp 工作台 ──────────────────────────┐
│ 顶部：文件 | 编辑 | 插入 | 视图 | 主题 | 导出 | 设置                        │
│ ┌─左侧栏─┬──────── 编辑区（Markdown）────────┬──── 实时预览（16:9）────┐ │
│ │ 大纲   │ # 我的演示文稿                     │  当前页幻灯片            │ │
│ │ 缩略图 │ ---                               │                          │ │
│ │ 文件树 │ ## 为什么选择 Markdown？            │  ◀ 3/12 ▶ [适应 ▾]      │ │
│ └────────┴───────────────────────────────────┴──────────────────────────┘ │
│ 状态栏：● 已保存 12:03:45 ｜ 学术蓝（内置）｜ 12 页 ｜ 16:9 ｜ 本地服务 ●   │
│ 右侧抽屉：主题画廊（点一下 → 全 deck ≤300ms 换装）                          │
└────────────────────────────────────────────────────────────────────────────┘
        ↓
导出：PDF（本机 Chrome/Edge 无头打印，无对话框）/ PPTX 图片版 / PNG / HTML
```

### 2.2 设计原则（按优先级）

1. **零安装零配置**：单文件 exe，双击即用，离线可用，不写注册表、不装服务、删掉即卸载。目标 exe ≤ 20MB（见 §3 实测预算，实际预计 6–12MB）。
2. **主题第一**：主题画廊是一等入口；所见即所得，一键切换，可导入、可收藏、可自定义。这是用户原话指向的核心痛点。
3. **三步出片**：双击 → 写/导入 → 选主题 → 导出。任何页面到"导出完成"≤ 2 次点击；首启 3 分钟内完成第一次导出。
4. **不锁定**：产出标准 `.md` + 标准 Marp 主题 CSS，可被 VS Code 扩展 / marp-cli 原样渲染；浏览器只是视图，文件是磁盘上的普通文本。
5. **中文友好**：中文界面、系统雅黑即可（实测无需打包中文字体）、中文路径、中文标点。
6. **可信的本地感**：仅监听 127.0.0.1 + 随机 token；界面上随时能看到"文件在哪个文件夹"；自动保存 + 刷新恢复 + 历史版本，让用户相信"网页 UI 不会弄丢我的文件"。

### 2.3 目标用户

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 技术分享者 / 开发者（主） | 技术分享、方案评审、周报 | 快、快捷键、代码高亮、导出 PDF/PPTX 发出去 |
| Markdown 爱好者 / 内容创作者 | 公众号、课程、长文配图 | "选个好看的主题就行"，不想碰 CSS/配置 |
| 学生 / 教师 / 临时汇报者 | 作业、答辩、被要求交 PPT | 打开就能写、模板多、导出 PPTX 能给别人改**

### 2.4 明确不做（防跑偏）

- ❌ 富文本 / 拖拽画布式 PPT 编辑器（坚持 Markdown + Marp 兼容）
- ❌ 私有格式、私有语法（`.md` 必须可被官方工具打开）
- ❌ 云同步 / 账号 / 协作（P2 再评估）
- ❌ PPTX 可编辑文字版（Marp 官方也只是图片版；可编辑版成本极高，v1.0 后都不做）
- ❌ 演讲者视图 / 演示模式（用户确认：直接用 PowerPoint 的演讲者视图，本产品只做编辑 + 预览 + 导出）
- ❌ Electron / Tauri 桌面壳（与"轻量"目标冲突，见 §3.2）
- ❌ 内置 Chromium / 打包浏览器引擎（100MB+，违反轻量目标）

## 3. 技术方案（已完成选型验证）

### 3.1 总体架构

```
┌────────────────── MarpWorkbench.exe（单文件，零运行时依赖）──────────────────┐
│ Rust（axum 0.8 + tokio + rust-embed 8），release 实测 demo = 0.50MB           │
│                                                                              │
│  HTTP 服务 127.0.0.1:<随机端口> + 一次性 token                                │
│  ├─ 静态资源（编译期内嵌）：前端构建产物 + marp-core 浏览器包 + 12 套主题      │
│  ├─ 工作区 API：文件树 / 新建 / 读写 / 重命名 / 删除 / 自动保存 / 历史快照     │
│  ├─ 主题 API：列表 / 读取 / 导入 CSS / 保存 / 删除 / 元信息解析                │
│  ├─ 导出 API：接收前端渲染好的 {html, css} → 生成打印页 → 调本机 Chrome/Edge   │
│  ├─ 原生对话框：rfd（打开/另存，中文路径 OK）                                  │
│  ├─ WebSocket：演讲者视图双窗同步（当前页/计时）                               │
│  └─ 生命周期：单实例、空闲退出、/api/shutdown、临时文件清理                    │
└──────────────────────────────────────────────────────────────────────────────┘
        ↑ 自动打开系统默认浏览器                       ↓ spawn（导出时）
┌──────────────────────────────┐        ┌────────────────────────────────────┐
│ 浏览器 UI（Chromium 系为主）  │        │ 本机已装 Chrome（优先）/ Edge        │
│ · CodeMirror 6 编辑器        │        │ headless --print-to-pdf 导出 PDF     │
│ · marp-core 浏览器渲染预览    │        │ （实测 3 页 4.13s / 100 页 8.34s，  │
│ · 主题画廊（DOM 缩放缩略图）  │        │  页面精确 960×540pt，中文可提取）    │
│ · 大纲/缩略图/备注/演示模式   │        │ 升级路径：单实例 CDP 截图（PPTX/PNG）│
└──────────────────────────────┘        └────────────────────────────────────┘
```

**核心设计：渲染在浏览器，导出用本机浏览器引擎。**
- marp-core 打包进前端（实测浏览器可直接运行，见 `marp-tech.md` §2.3），预览/主题切换全部本地毫秒级。
- 导出时前端把渲染好的 `{html, css}` POST 给服务端，服务端生成**静态打印页**（`@page{size:1280px 720px;margin:0}` + 逐页分页），再用本机 Chrome/Edge 无头打印。这样导出**不需要服务端 JS 引擎**，也没有"打印时 JS 没渲染完"的时序风险；且与预览**同源同参数**（解决 Marp 社区"预览≠导出"的投诉）。
- 代价：前端首包要带 marp-core（3.85MB min / **1.20MB gzip**，本地 HTTP 加载很快）；换来 exe 从 ~80MB 降到 ~10MB。

### 3.2 为什么是 Rust 单文件 exe（实测对比）

| 方案 | 单文件体积 | 冷启动 | 目标机依赖 | 结论 |
|---|---|---|---|---|
| **Rust（axum + tokio + rust-embed）** | **0.50MB 实测 demo**（全量资源内嵌后预计 6–12MB） | <100ms 级 | 零（仅需系统浏览器做导出） | ✅ **选定** |
| Go（net/http + embed） | 估算 5–12MB | 快 | 零 | ⭕ 备选（本机未装，团队更熟 Go 时可平替，前端/导出链路完全复用） |
| .NET 7 单文件 | 估算 12–15MB | 100–300ms | 零 | ⭕ 备选（体积居中，.NET 7 已非 LTS） |
| Node 22 SEA | **≥ 79.4MB**（node.exe 实测 79.4MB） | 中 | 零 | ❌ 体积不达标 |
| Bun `--compile` | 估算 50–100MB | 快 | 零 | ❌ 体积不达标 |
| Electron 44 | 安装包 90–110MB | 1–3s | 自带 Chromium | ❌ 与"轻量"直接冲突 |
| Tauri 2 | exe 3–10MB | 快 | WebView2 | ❌ 官方无打印/PDF API（实测 `@tauri-apps/api` 2.12.4 无 `print`；需自己调 WebView2 COM 或外挂浏览器，反而更复杂） |

> 备选调整成本很低：服务端只做 HTTP/文件/导出编排，Go 可在不改前端与导出设计的情况下替换。

### 3.3 关键链路实测数据（直接作为性能预算）

| 链路 | 实测结果 | 来源 |
|---|---|---|

| PDF 3 页（含中文/深色背景/渐变） | 4.13s，3 页均 **960×540pt = 1280×720px**，106.7KB，中文可提取、无页眉页脚、背景已打印、文本坐标与 CSS 1:1 无裁切 | packaging |
| PDF 100 页 | **8.34s**，100 页全部 960×540pt，384.3KB（纯矢量，约 3.8KB/页） | packaging |

| marp-core 浏览器冷/热渲染 | 362ms / **100ms**（4 页含中文/公式/代码） | marp-tech |

### 3.4 导出管线设计（本计划的核心承诺）

| 格式 | 主通道 | 质量 | 兜底 / 升级 |
|---|---|---|---|
| **PDF（P0）** | 前端渲染 → POST `{html,css}` → 服务端生成静态打印页 → 本机 Chrome（优先）无头 `--print-to-pdf` | 矢量文本、可搜索复制、主题/渐变/背景 1:1、中文正常 | Chrome 缺失 → Edge（需落盘检测 + kill）→ 再不行回退浏览器 `window.print()` 并给操作引导 |
| **PPTX 图片版（P0）** | 服务端原生截图（单实例 CDP `Page.captureScreenshot`，2x=2560×1440）→ 前端 pptxgenjs 组装（13.333×7.5in、每页背景图、备注写入 notes） | 与 marp-cli 图片版同级（主题保真）；**不可逐字编辑**（UI 明示） | M0 若 CDP 成本超预期 → 降级浏览器 html-to-image 截图（有轻微样式差异，标注"快速版"）；v0.2 再补 CDP |
| **PNG（P1）** | 同 PPTX 截图通道，逐页 1x/2x 打包 zip | 原生级 | 同上 |
| **HTML 单文件（P0）** | 前端渲染结果 + 主题 CSS + 本地字体内联 → 单文件 | 离线双击可播 | — |
| **备注** | `comments[i]` 按页提取 → PPTX notes / 演讲者视图 / TXT | — | — |

**导出防坑清单（实测踩过，必须实现）：**
1. 每次导出用独立 `--user-data-dir=%TEMP%\MarpWorkbench\chrome-xxx`，结束清理，避免与用户浏览器冲突。
2. 显式传 `--no-pdf-header-footer`（防版本差异带上 URL/日期）+ `--virtual-time-budget`。
3. Edge 打印完不退出 → 轮询 PDF「存在且大小稳定 ≥300ms」后 `taskkill /T /F`；杀早了会截断 PDF。
4. 打印页必须有 `@page{size:1280px 720px;margin:0}`、`print-color-adjust: exact`、逐页 `break-after: page`（最后一页 auto）。
5. 服务进程与打印进程**解耦**（异步 spawn；同进程同步阻塞会让本地 HTTP 请求饿死 —— 实测踩过）。
6. 导出 URL 必须带本次 token 且校验属于本服务，防本机其他程序诱导打印任意页面。
7. 浏览器探测顺序：Chrome 标准路径 / App Paths 注册表 → Edge → 失败给出可执行提示（"安装 Chrome/Edge 或改用浏览器打印"）。

### 3.5 离线策略（实测发现的一号坑）

**现状：** marp-core 默认会引用外网资源——KaTeX 字体（约 60 条 jsDelivr URL）、gaia 主题的 bunny.net 网络字体、twemoji CDN。实测含这些资源的 deck 让 marp-cli 等待 30s 超时失败。

**必须做到"0 外网请求"（验收项）：**
1. 默认数学引擎用 **MathJax**（SVG 输出，无字体依赖，离线最稳）；用户 deck 若显式 `math: katex`，则把 **KaTeX 20 个 woff2（260KB）本地化**并设置 `katexFontPath` 指向应用内资源。
2. gaia 主题的网络字体 `@import` 在打包时替换为本地/系统字体。
3. emoji 关闭 twemoji CDN（用 Unicode 或本地资源）。
4. 验收方式：导出时用 DevTools/请求拦截检查**无任何非 127.0.0.1 请求**；断网环境跑全流程。

### 3.6 安全与服务生命周期（本地 Web 形态必备）

| 项 | 方案 |
|---|---|
| 网络暴露 | 只 bind `127.0.0.1`；随机端口；不改防火墙 |
| 访问控制 | 启动生成一次性随机 token，浏览器首开 URL 带 `?token=`，之后 API 走 header；前端静态资源与 token 绑定（防本机其他网页扫描端口） |
| 单实例 | Windows named mutex；二次双击 → 探测已有实例 → 直接打开已有 URL（新标签页） |
| 退出 | ① 页面「设置 → 退出应用」（先全部保存再停服务）；② 无页面连接空闲 10 分钟自动退出（可配置 5/10/30/从不）；③ 可选托盘图标（P1） |
| 临时文件 | 全部在 `%TEMP%\MarpWorkbench\`，启动清理 >7 天旧目录；退出清理本次导出临时目录 |
| 数据目录 | 便携模式：exe 同目录 `data\`（优先）；不可写时回退 `%APPDATA%\MarpWorkbench\`；UI 明示路径并可"打开所在文件夹" |
| 异常 | 未捕获错误写 `data\logs\`（可一键打开），UI 显示可读提示 + 下一步建议 |

## 4. 功能范围（P0 / P1 / P2）

## 5. 核心差异化：主题系统设计

### 5.1 主题来源与存储

| 类型 | 位置 | 说明 |
|---|---|---|
| 内置主题 | exe 内嵌（只读） | Marp 原生 3 套（default/gaia/uncover，字体本地化）+ **自研 12 套** |
| 我的主题 | `%APPDATA%\MarpWorkbench\themes\*.css`（便携模式 `data\themes\`） | 用户导入/另存/新建，重启保留 |
| 项目主题 | 工作区 `.marp\themes\*.css` | 随 deck 目录一起迁移/分享 |

### 5.2 主题包格式（向下完全兼容 Marp）

```css
/* @theme business-blue */
@import 'default';

/* @name 商务蓝 */
/* @tags 商务,汇报,蓝色 */
/* @thumbs 封面,内容,代码,表格 */   ← 可选：画廊缩略图取样页

:root { --brand: #1e5eff; }
section { ... }
```

> 注：`@import 'default';` 必须是真实 CSS @import（不能写在注释里，否则不生效）；其余 `@name/@tags` 等为 Marp 忽略的扩展注释。

- 只用 Marp/Marpit 原生注释语法 + 自定义扩展注释（Marp 忽略未知注释，**官方工具可原样渲染**）。
- 应用内解析 `Theme.meta`（name/author/size/auto-scaling）驱动画廊；自定义主题的尺寸从 `meta.size` 或渲染后 SVG viewBox 读取（实测自定义主题 `width/height` 为 undefined）。

### 5.3 主题画廊交互（本产品最重要的 UI）

```
┌─ 主题（右侧抽屉 360px）────────────────────────────────┐
│ [搜索主题…]                          ★收藏  最近使用   │
│ [全部] [推荐] [商务] [科技] [学术] [极简] [创意] [我的] │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐               │
│ │ 真实内容  │ │ 真实内容  │ │ 真实内容  │  220×124 卡片  │
│ │ 缩略图    │ │ 缩略图    │ │ 缩略图    │  名称+标签    │
│ │商务蓝 ✓  │ │科技深色  │ │学术白    │  3 色块+字体   │
│ └──────────┘ └──────────┘ └──────────┘               │
│ hover：预览区临时全 deck 切换（不写文件，移开复原）      │
│ 点击：立即应用（≤300ms）+ "已应用「商务蓝」撤销" toast   │
│ ↑↓：连续轮播试穿；Enter：应用；Esc：撤销                 │
│ [＋ 新建主题]  [↓ 导入 .css]                            │
└────────────────────────────────────────────────────────┘
```

实现要点（均有实测依据）：
- **缩略图用 DOM 缩放实时渲染**（每主题渲染 deck 前 3 页 → `transform: scale()` 塞进卡片），**不用截图**：0.3–1.8ms/个、清晰、主题 CSS 改了立即更新；html-to-image 位图方案慢 50–100 倍且会丢渐变/高亮，仅用于"导出主题包预览图"。
- 渲染方式：同一 Marp 实例 `themeSet` 注册全部主题，缩略图按主题改写 front-matter 后渲染（懒加载 + 可视区域渲染，避免 15 个预览同时渲染卡顿）。
- **防选择过载**：默认显示"推荐 6 套"；分类 + 搜索 + 收藏 + 最近使用；高级用户展开全部。推荐逻辑先按场景标签，不做算法。
- **零破坏试穿**：hover / 方向键只改预览，不落盘；点击才写入 front-matter，可 Undo。
- 主题详情可暴露 `class` 变体（如 gaia invert）为开关。

## 6. 界面信息架构与核心流程

### 6.1 页面结构

```
本地服务 127.0.0.1:<port>
├─ /                     首页 / 工作区（最近文件、新建、导入、工作区路径、首启引导）
├─ /edit/:deckId         编辑器（顶部菜单 + 左侧大纲/缩略图/文件树 + 中央编辑 + 右侧预览 + 主题抽屉 + 导出面板 + 状态栏）
└─ /settings             设置（工作区、默认主题、退出应用、隐私说明、关于）
```

### 6.2 三个核心流程

**A. 双击 → 写 → 选主题 → 导出（目标 ≤3 分钟）**
1. 双击 exe → 浏览器打开首页（显示工作区真实路径 + "打开所在文件夹"）
2. 新建（或首启示例 deck）→ 光标就位，右侧实时预览
3. 点「主题」→ 画廊 → hover 试穿 → 点卡片应用（≤300ms，自动保存）
4. 点「导出」→ 选 PDF → 进度 → 完成 toast：「打开 PDF」「打开所在文件夹」

**B. 导入现成 md**
1. 拖 `.md` 进页面 → 复制到工作区 → 出现在最近文件
2. 识别是否 Marp 文档（无 `marp: true` 询问是否作为演示文稿打开）
3. 主题检查：引用未知主题 → 提示"自动查找 / 用内置相似主题 / 导入 CSS"
4. 资源检查：缺失图片列清单（可定位/替换）；相对路径按 md 目录解析

**C. 自定义主题**
导入/另存 → 编辑器实时预览 → 保存为"我的主题" → 当前 deck 应用 → 可分享 `.css` 给别人拖入。

### 6.3 浏览器形态的交互规范（必须处理）

- 拦截 `Ctrl+S`（保存+快照）、`Ctrl+Shift+S`（另存为）、`Ctrl+N`（新建）、`Ctrl+O`（导入）、`Ctrl+P`（改打开导出面板，不触发浏览器打印）。
- `beforeunload` 只在有未保存改动时提示（正常自动保存后不出现）。
- 全屏 / 演讲者窗必须在用户点击手势内调用（防弹窗拦截）；无第二屏时降级单窗并提示"拖到投影仪"。
- 整页 drop zone（导入 md/图片/CSS），带高亮，避免与浏览器默认打开文件冲突。
- 布局用 rem/响应式，1280–1920 宽度可用；提示不要用浏览器缩放代替应用缩放。

## 7. 技术实现细节

### 7.1 服务端 API（Rust/axum）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活检测（幂等，供单实例探测） |
| GET | `/api/workspace/tree` | 工作区文件树 |
| POST | `/api/workspace/import` | 导入文件（multipart 或路径）到工作区 |
| GET/PUT | `/api/decks/:id` | 读取 / 保存 `.md`（自动保存走 PUT，带 `if-match` 版本号防覆盖） |
| POST | `/api/decks` / `/rename` / `/delete` | 新建 / 重命名 / 删除（回收站式：先移到 `.trash`） |
| GET | `/api/decks/:id/history` | 历史快照列表 / 回滚 |
| GET/POST | `/api/themes` | 列出 / 导入主题 CSS，返回解析后的 `Theme.meta` |
| PUT/DELETE | `/api/themes/:name` | 保存 / 删除自定义主题 |
| POST | `/api/export/pdf` | body `{html, css, title, pageSize}` → 生成打印页 → 调用无头浏览器 → 返回下载 URL |
| POST | `/api/export/capture` | body `{html, css, slideCount, scale}` → 返回逐页 PNG URL（PPTX/PNG 用） |
| POST | `/api/export/html` | 单文件 HTML 落盘 |
| GET | `/api/export/file/:token` | 下载导出文件（`Content-Disposition` 中文名用 `filename*=UTF-8''`） |
| POST | `/api/dialog/open` `/save` | rfd 原生对话框（服务端弹窗） |
| POST | `/api/shutdown` | 保存全部 → 停服务 |
| WS | `/ws/present` | 演讲者双窗同步 |

**鉴权：** 所有 `/api/*` 要求 `X-Token`；token 在启动时生成，浏览器首开 URL 带 `?token=`，前端存 sessionStorage 后续带 header；打印页与导出下载 URL 内嵌一次性 token。

### 7.2 前端技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 构建 | Vite 7 + TypeScript | 快，产物可直接内嵌 |
| 框架 | **Vue 3（`<script setup>`）** | 轻、上手快、单文件组件适合面板式 UI |
| 编辑器 | CodeMirror 6 | 比 Monaco 轻；语法高亮/快捷键/自定义分页线装饰 |
| 渲染 | `@marp-team/marp-core` 4.4.0（浏览器 IIFE） | 与官方同源；iframe `srcdoc` 注入保证内联 helper 执行 |
| 预览 | iframe srcdoc + postMessage 同步 | 隔离主题 CSS；`browser()` helper 手动调用（`innerHTML` 不会执行内联脚本 —— 实测坑） |
| 主题缩略图 | 同实例多主题渲染 + DOM `transform:scale` | 实测 0.3–1.8ms/个，保真 |
| PPTX | pptxgenjs（浏览器） | 实测可复刻 marp-cli 图片版；13.333×7.5in 版式 + 背景图 + notes |
| PNG | 服务端 CDP 原生截图（主）/ html-to-image（降级） | 保真优先 |
| 状态 | Pinia（或组合式函数） | 简单够用 |
| 测试 | Vitest + Playwright（对本地服务 E2E） | 见 §10 |

## 9. 风险与对策（按调研实测校准）

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| R1 | **无头浏览器行为随版本变化**（headless 参数、Edge 不退出、旧版本无 `--headless=new`） | PDF 导出失败（核心功能） | 版本探测 + 最低版本要求；Edge 用「落盘稳定再杀」；失败回退 `window.print()` 并给引导；M0 在 Chrome/Edge 双版本矩阵实测 |

## 10. 测试与验收

### 10.1 产品级验收（v0.1 发布门槛）

1. **开箱**：干净 Windows 10/11 机器（无 Node、无 VS Code、断网），双击 exe → 5s 内浏览器出现工作台，全程无黑窗；重复双击复用已有实例。
2. **三步出片**：新建 → 写 3 页 → 选主题 → 导出 PDF ≤ 3 分钟，零命令行、零配置。
3. **PDF 质量**：30 页 ≤15s；页面精确 1280×720（960×540pt）；无白边/页眉页脚；背景与渐变正确；中文可复制；与预览逐页一致（封面/内容/代码/结尾 4 页人工对比）。
4. **PPTX**：页数=幻灯片页数、16:9、PowerPoint/WPS 打开无修复提示、备注写入；UI 明示图片版。
5. **主题**：内置 ≥12 套离线可用；画廊缩略图用当前 deck 真实内容；切换 ≤300ms；`↑↓` 可连续试穿；导入外部 CSS 立即生效；"我的主题"重启保留。
6. **本地信任**：编辑停止 1s 内落盘；强杀进程重开丢 ≤1s；刷新 ≤1s 恢复现场；最近文件 ≥10 条；历史快照可回滚。
7. **大 deck**：100 页 deck 编辑/切换主题/导出不卡死（预览按当前页渲染，导出走独立进程不阻塞 UI）。
8. **离线**：断网全流程可用；全程 0 非 127.0.0.1 请求（拦截验证）。
9. **兼容**：导出的 `.md` 放 VS Code + Marp 扩展渲染效果一致；导出 HTML 离线双击可播。
10. **轻量**：exe ≤20MB、单文件、免安装、删目录即卸载、无注册表/服务残留、退出无残留进程。

### 10.2 工程验收

- 构建：`cargo build --release` + `pnpm build` 一条命令出包；exe 带图标/版本信息；构建可复现（锁定依赖版本）。
- 测试：Rust 单测（主题解析/路径/导出参数/打印页生成）；前端 Vitest（编辑器/主题/front-matter）；Playwright E2E（启动→新建→编辑→切主题→导出 PDF→文件校验）；CI smoke：`--version`、`/healthz` 200、3 页 PDF 页数/尺寸断言、exe 体积断言。
- 文档：README（使用/系统要求/退出方式/常见问题）、DEVELOPMENT（构建/架构）、CHANGELOG。
- 无阻塞 TODO；已知问题列表 + 规避方案。
